# 대표 실습 · 문의 30건과 메일 60개 인수인계

모든 기관·사건·번호·승인은 교육용 가상 자료입니다. 실제 기관의 신청·발송·승인을 실행하지 않습니다. 자료 버전 1.8.0.

## 업무 상황과 맡길 범위

담당자가 교대하는 오후, 두 기관의 공동연수 문의 30건이 남아 있습니다. 문의마다 첫 메일과 추가 회신이 있고, 운영 기준·변경 승인·접수 및 장비 대장에 필요한 사실이 흩어져 있습니다. 같은 문장의 요약보다 **메일을 문의별로 묶고, 최신 의사와 확인된 처리 상태를 나누어 여러 문서의 근거를 연결하는 일**이 필요합니다.

AI에는 전체 처리표와 답장·확인 요청·공지 수정 초안을 작성하도록 요청합니다. 사람은 자료를 읽을 순서와 처리 결과를 검토하고 승인 범위를 판단합니다. 초안이 실제로 도움이 되었는지는 같은 사례의 누락·오류·근거 확인 부담을 비교해서 기록합니다. 자료가 많다는 이유만으로 AI가 더 빠르거나 정확하다고 결론 내리지 않습니다.

## 파일과 입력 방법

| 파일 | 역할 | AI 입력 |
|---|---|---|
| 31 운영기준 | 최초 일정·기관별 배정·자격·처리 원칙 | 37번에 포함 |
| 32 변경승인 | 최신 승인·개별 예외·공지 수정 요청 | 37번에 포함 |
| 33 문의메일 | Q01~Q30·ML001~ML060 | 37번에 포함 |
| 34 접수대장 | 40행 신청 상태·기기 배정 | 37번에 포함 |
| 35 비교샘플 | 같은 세 문의의 원문 발췌·빈 처리표 | 수작업용, AI에 추가하지 않음 |
| 36 복사 질문 | 첫 지시문·선택 수정 질문 | 첫 지시만 복사 |
| 37 원문 네 개 합본 | 31~34를 그대로 묶은 TXT 파일 | **이 파일 한 개 첨부** |
| 90 해설 | 정답과 예시·검토 근거 | 활동 뒤 공개, AI에 넣지 않음 |

새 대화에서 **37_원문네개_합본.txt를 첨부하고 첨부 완료를 확인한 뒤**, 36번의 짧은 첫 질문을 보냅니다. 31~34를 중복 첨부하거나 35·90을 입력 소스로 섞지 않습니다. 합본 파일 안에는 원문만 있고 정답은 없습니다. 응답에서 ML060과 마지막 L9를 읽을 수 있는지 확인하게 하되, AI가 읽었다고 말한 사실만으로 전체 내용이 정확하다고 판단하지 않습니다.

긴 원문 전체를 채팅 입력란에 붙여 넣는 방법은 수업의 기본 방법으로 사용하지 않습니다. 준비 과정의 실제 테스트에서 입력 끝부분이 전달되지 않은 사례가 있었고, 자동화 입력과 서비스 제약 중 원인은 확정하지 못했습니다. 붙여넣기가 항상 실패한다는 뜻은 아니지만 입력됐는지 확인하지 않은 채 결과를 신뢰하지 않습니다. 첨부가 지원되지 않거나 업로드·한도 문제로 진행이 멈추면 원문과 교사 해설을 이용해 검토 활동을 하고 AI 실행 미완료를 기록합니다.

실제 검증에서 37번 합본 첨부 후 전체 요청은 도움 불가 응답을 받았습니다. 후속 파일 읽기 확인과 세 행 요청에서는 ML060=Q30, L9=담당 교대 메모와 Q01 확정·Q04 취소·Q12 대기를 확인했습니다. 그러나 30행 표만 다시 요청해도 Q07 도중 첨부를 찾을 수 없다는 응답으로 중단되어 **30행 일괄 완주는 미확인**입니다. 36번 질문은 수업의 전송 계획이며 실행 성공을 보장하지 않습니다.

**5분 생성 구간 안에 실패하거나 중단되면 반복 질문을 보내지 말고 90번 교사 예시와 원문을 대조합니다.** 90번은 원문 기반 제작 자료이며 AI 출력이 아닙니다. 비교 기록에도 ‘AI 응답’과 ‘교사 예시’를 구별하고, 30행이 없으면 미완료 범위를 남깁니다.

## 18분 진행

| 시간 | 할 일 | 남길 결과 |
|---|---|---|
| 0~3분 | 35번 발췌에서 Q01·Q04·Q12를 직접 읽고 같은 형식의 처리표 세 행 작성 | 직접 작성한 세 행. 끝내지 못한 칸은 미완성 |
| 3~8분 | 37번 파일 첨부 후 질문 1회. 응답 대기 중 문서 기준일·기관 구분 확인 | 전체 30행·답장 5개·확인 요청·공지 수정의 **초안** |
| 8~13분 | AI 표의 Q01·Q04·Q12 세 행을 원문에 대조 | 상태·안내·담당·근거 확인 기록. 실제 확인한 칸만 표시 |
| 13~18분 | 오류 직접 수정 또는 선택 수정 질문 1회, 검토 범위와 도움·부담 기록 | 검토 완료한 세 행과 미검토 결과를 구분하여 저장 |

18분 안에 전체 30건을 완전히 검토했다고 간주하지 않습니다. 세 사례도 시간이 부족하면 미완료로 표시합니다. 모든 ID가 있는지 세는 일은 **누락 점검**이며 각 행의 사실 확인을 대신하지 않습니다. 실제 업무에 적용하기 전에는 담당자가 전체 해당 행·답장·공지의 상태와 근거를 검토해야 합니다. 이 가상 자료와 답장 자체를 실무 수신자에게 발송하지 않습니다.

## 이번에 만드는 결과

1. Q01~Q30 처리표 30행: 문의ID / 최신 요청 / 확인된 상태 / 지금 안내할 한 문장 / 추가 확인(담당 역할) / 근거ID.
2. Q01·Q04·Q10·Q18·Q27 답장 초안 5개: 제목과 본문 250~400자, 내부 근거 메모 별도.
3. 담당 역할별 확인 요청 묶음: 관련 문의ID와 질문·아직 확정하지 못한 판단.
4. 구공지 N01~N03 수정표 3행: 잘못된 문구·수정 문장·근거·게시 상태.
5. 수업 중 직접 확인한 세 행의 검토 기록과 나머지 미검토 표시.

## 비교는 같은 세 행의 품질부터

직접 작성한 Q01·Q04·Q12와 AI의 30행에서 뽑은 같은 세 행을 나란히 둡니다. 두 방법의 표 열과 판단 시각은 같습니다. 확인된 상태, 확정해서는 안 되는 내용, 다음 안내, 확인 담당, 문서 근거를 대조합니다. 수작업에 쓰는 발췌와 AI 전체 입력의 자료량·처리량이 다르므로 **3건 수작업 시간과 30건 AI 시간으로 속도 배율이나 시간 절감률을 계산하지 않습니다.** 답장 5개 작성 시간도 세 행 수작업 시간과 비교하지 않습니다.

| 기록할 항목 | 직접 작성 세 행 | AI의 같은 세 행 |
|---|---|---|
| 완료한 행·칸 수 | | |
| 상태를 잘못 확정한 건 | | |
| 누락된 안내·확인 항목 | | |
| 실제로 확인한 근거 문단 | | |
| 사람이 고친 문장과 이유 | | |

AI 전체 작업의 준비·입력·응답 대기·검토·수정 시간은 별도 기록합니다. 반복 메일 묶기와 초안 전사가 도움이 되었는지, 문서 확인이나 수정이 더 필요해졌는지를 구체적으로 씁니다. “AI가 검증했다”는 말 대신 확인한 문단과 고친 판단을 남깁니다.

## 요청량과 한도 대응

권장 전송 계획은 첫 질문 1회와 오류가 있을 때 선택 수정 1회입니다. 이는 무료 계정의 제공 횟수가 아닙니다. 파일 처리·재전송·분할 입력·추가 질문은 사용량에 영향을 줄 수 있습니다. 한도가 생기면 반복 전송하지 않고 원문으로 세 행을 검토합니다. 새 대화는 자료를 구분하기 위한 것이며 남은 사용량을 늘리는 방법으로 안내하지 않습니다. 유료 결제나 계정 공유를 수업의 필수 조건으로 두지 않습니다.
